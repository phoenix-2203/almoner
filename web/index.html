How it works

1

A person signs the rules

Purpose, allowed categories, blocked terms, sellers, budget, per-purchase cap and an approval line. One task, one mandate.

2

The vault issues the agent's key

A NEAR function-call key on the vault's own account. It can call three methods. It can't transfer, add keys or call anything else.

3

Sellers sign every price

The agent forwards a signed quote. The vault checks the signature on-chain, so nobody can edit the price, the item or the payee.

4

Escrow, then proof

Funds wait until the seller delivers. Accepted work is paid. Junk or silence is refunded and the seller goes on hold.

What makes it different

Leak the key, lose nothing

On most agent wallets a leaked key is a drained wallet. Here the protocol itself limits the key, so we publish it.

Within budget isn't enough

IntentLock refuses purchases that fit the budget but not the purpose, even when the item is disguised: G1FT-c@rd is still a gift card.

Reputation you can't fake

A seller's score counts only purchases settled through escrow. Faking it costs real payments.

Break it

The private key of this vault's agent is published in the repository on purpose. One command signs six theft attempts with it and shows how each is stopped: four by the NEAR protocol, two by the vault, which records them on-chain.

cd almoner/ts && npm ci
